# goope

A Go implementation of the [Boldyreva Order-Preserving Encryption](https://faculty.cc.gatech.edu/~aboldyre/papers/bclo.pdf) (OPE) scheme, ported from [tonyo/pyope](https://github.com/tonyo/pyope).

OPE encrypts integers to integers while preserving their relative order: if `x < y`, then `OPE(x) < OPE(y)`. This allows to perform range queries and comparisons directly on encrypted data stored in a database, without needing to decrypt it first.

> **Security Warning**. OPE by definition leaks the ordering of plaintexts. It is not a general-purpose encryption scheme and should only be used where order-leakage is an acceptable trade-off (e.g., an encrypted index in a trusted-enclave architecture). If you need confidentiality without order-leakage, consider using a different encryption scheme (e.g., AES-GCM).

## Quick Start

```go
package main

import (
    "fmt"
    "log"

    "github.com/alessandrofoglia07/goope"
)

func main() {
    // Your secret key, must be kept private
    key := []byte("your-32-byte-secret-key-here")

    // Create a cipher with default ranges:
    // - plaintext space: [0, 32767] (2^15 values)
    // - ciphertext space: [0, 2147483647] (2^31 values)
    ope, err := goope.NewOPE(key, nil, nil)
    if err != nil {
        log.Fatal(err)
    }

    plaintext := 1337
    ciphertext, err := ope.Encrypt(plaintext)
    if err != nil {
        log.Fatal(err)
    }
    fmt.Printf("Plaintext: %d, Ciphertext: %d\n", plaintext, ciphertext)

    decrypted, err := ope.Decrypt(ciphertext)
    if err != nil {
        log.Fatal(err)
    }
    fmt.Printf("Decrypted: %d\n", decrypted)
    // Output:
    // Encrypt(1337) = 123456789 (example, actual value depends on the key)
    // Decrypt(123456789) = 1337
}
```

## How it works

Encrypting a value works like a binary search:

1. Start with a plaintext range (e.g. [0, 32767]) and a ciphertext range (e.g. [0, 2147483647]).
2. At each step, the algorithm picks the midpoint of the ciphertext range and asks: _"which plaintext value does this midpoint correspond to?"_. It answers the question using the hypergeometric distribution, a way of splitting a population proportionally, seeded with a key-derived pseudorandom bit stream.
3. Depending on whether the plaintext is above or below the midpoint, it zooms into the left or right half of both ranges.
4. Repeat until the plaintext range collapses to a single value, at which point the corresponding ciphertext is returned.

Because every step is seeded deterministically with the key, the same plaintext will always produce the same ciphertext. Because each split is proportional, the order is always preserved.

Decryption runs the algorithm in reverse: given a ciphertext, it performs the same splits to find the corresponding plaintext.

The pseudorandom bit stream for each step is generated by:

```
HMAC-SHA256(key, str(midpoint))  ->  32-byte AES-256 key
AES-256-CTR(key, IV=0, input=0)  ->  infinite pseudorandom bit stream
```

## Custom Ranges

By default, the plaintext space is [0, 32767] and the ciphertext space is [0, 2147483647]. You can customize these ranges when creating the cipher, as long as the output range is at least as large as the input range:

```go
// Encrypt timestamps (seconds since epoch, roughly 2024..2035) into a much wider ciphertext space.
inRange, _ := goope.NewValueRange(1_700_000_000, 1_900_000_000)
outRange, _ := goope.NewValueRange(0, 1<<62-1)

ope, err := goope.NewOPE(key, &inRange, &outRange)
```

Ranges can also be negative:

```go
// Temperatures in Celsius (-100..+100) mapped to a wide positive space.
inRange, _ := goope.NewValueRange(-100, 100)
outRange, _ := goope.NewValueRange(0, 1<<31-1)

ope, err := goope.NewOPE(key, &inRange, &outRange)
```

Equal range produce an identity mapping (plaintext = ciphertext):

```go
inRange, _ := goope.NewValueRange(0, 1000)
outRange := goope.Copy() // same range

ope, _ := goope.NewOPE(key, &inRange, &outRange)
ct, _ := ope.Encrypt(123)
fmt.Println(ct) // 123
```

## Using it as an encrypted database index

The main use case for OPE is storing encrypted values in a database column while keeping the ability to run `ORDER BY`, `<`, `>`, and `BETWEEN` queries (e.g. see [Gardbase](https://github.com/qodesrl/gardbase)).

```go
// Suppose you store user ages in a DynamoDB table and want to keep the values encrypted, but still be able to query users by age range.

type User struct {
    ID           string
    EncryptedAge int
}

func encryptAge(ope *goope.OPE, age int) (int, error) {
    return ope.Encrypt(age)
}

// At query time, encrypt the range boundaries with the same key and pass them to your database query.
func queryAgeRange(ope *goope.OPE, minAge, maxAge int) (int, int, error) {
    encMin, err := ope.Encrypt(minAge)
    if err != nil {
        return 0, 0, err
    }
    encMax, err := ope.Encrypt(maxAge)
    if err != nil {
        return 0, 0, err
    }
    return encMin, encMax, nil
    // then SELECT * FROM users WHERE encrypted_age BETWEEN encMin AND encMax
}
```

## API Reference

### `NewOPE(key []byte, inRange, outRange *ValueRange) (*OPE, error)`

Creates a new OPE cipher.

- `key` is a secret key of any length (32 bytes recommended).
- `inRange` is the plaintext range (inclusive). If `nil`, defaults to [0, 32767].
- `outRange` is the ciphertext range (inclusive). If `nil`, defaults to [0, 2147483647]. Must be at least as large as `inRange`.

Returns `ErrInvalidRanges` if `outRange.Size() < inRange.Size()`.

### `(o *OPE) Encrypt(plaintext int) (int, error)`

Encrypts a plaintext integer to a ciphertext integer. Returns `ErrOutOfRange` if the value is outside `inRange`.

### `(o *OPE) Decrypt(ciphertext int) (int, error)`

Decrypts a ciphertext integer back to plaintext. Returns `ErrOutOfRange` if the value is outside `outRange`, or `ErrInvalidCiphertext` if the ciphertext was not produced by this key and range configuration.

### `NewValueRange(start, end int) (ValueRange, error)`

Creates a `ValueRange`. Returns `ErrInvalidRangeLimits` if `start > end`.

### `ValueRange` methods

| Method                 | Description                                             |
| ---------------------- | ------------------------------------------------------- |
| `Size() int`           | Returns the size of the range (inclusive on both ends). |
| `Contains(n int) bool` | Returns true if `n` is within the range.                |
| `Copy() ValueRange`    | Returns an independent copy of the range.               |

### Sentinel Errors

| Error                   | Meaning                                                       |
| ----------------------- | ------------------------------------------------------------- |
| `ErrOutOfRange`         | Value is outside the defined range.                           |
| `ErrInvalidCiphertext`  | Ciphertext does not match any valid plaintext under this key. |
| `ErrInvalidRanges`      | Range configuration is invalid.                               |
| `ErrInvalidRangeLimits` | `start > end` when creating a `ValueRange`.                   |

## Security Considerations

- **Order leakage**. OPE leaks the order of plaintexts by definition. Do not use it if order-leakage is not acceptable for your use case.
- **Key management**. The security of OPE depends entirely on the secrecy of the key.
- **No integrity**. OPE does not provide integrity guarantees. An attacker who can write to the ciphertext column can substitute any value in the output range and it will decrypt without error (as long as it lands on a valid encrypted value). Pair it with a separate integrity mechanism if needed.
- **Ciphertext space**. The output range should be significantly larger than the input range to minimize the probability of collisions. A small ratio reduces security.
